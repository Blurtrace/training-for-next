## ✨ Propósito del proyecto

**BidHub** es una *casa de subastas online* diseñada para que los estudiantes y entusiastas aprendan y profundicen en el ecosistema **Full‑Stack de Next.js 16**. El objetivo es ofrecer una plataforma real‑ista donde los usuarios pueden crear, ofertar y administrar subastas, mientras se exploran conceptos avanzados como autenticación con cookies httpOnly, manejo de transacciones, concurrencia optimista y despliegue en Vercel.

---

## 📦 Tecnologías (badges)

- **Framework**: Next.js 16 (App Router) – TypeScript (strict, sin `any`).
- **ORM / Base de datos**: TypeORM + PostgreSQL alojado en Supabase.
- **Validación**: Zod (esquemas tipados y reutilizables).
- **Autenticación**: jsonwebtoken + bcrypt, tokens de acceso/refresh en cookies httpOnly, secure, SameSite.
- **Estilos**: Tailwind CSS + shadcn/ui.
- **i18n**: i18next / react‑i18next (es / en) con selector visible.
- **Tests**: Jest.
- **Concurrencia**: Optimistic locking (`@VersionColumn`).
- **Extras**: rate‑limiting (login / pujas), idempotencia de pujas, Docker & Docker‑Compose, CI pipeline, pruebas de reglas de negocio.

## 🚀 Instalación y puesta en marcha

> **Requisitos previos**
>
> - Node.js ≥ 20 (recomendado). 
> - npm ≥ 10 (se usará `npm ci`).
> - Docker (para la versión en contenedor).
> - Cuenta en **Supabase** para crear una base de datos PostgreSQL.
>
> ### 1. Clonar el repositorio
>
> ```bash
> git clone <https://github.com/Blurtrace/training-for-next.git>
> cd training-for-next
> ```
>
> ### 2. Instalar dependencias (congeladas)
>
> ```bash
> npm ci
> ```
>
> ### 3. Configurar variables de entorno
>
> Copia el archivo de ejemplo y rellénalo con tus valores:
>
> ```bash
> cp .env.example .env
> ```
>
> - `DATABASE_URL` – cadena de conexión de Supabase (PostgreSQL).
> - `JWT_ACCESS_SECRET` – cadena aleatoria ≥ 32 bytes (usada para firmar el access‑token).
> - `JWT_REFRESH_SECRET` – cadena aleatoria ≥ 32 bytes (para el refresh‑token).
> - `ACCESS_TOKEN_EXPIRES_IN` – p.ej. `15m`.
> - `REFRESH_TOKEN_EXPIRES_IN` – p.ej. `7d`.
>
> ### 4. Ejecutar migraciones y seed
>
> ```bash
> npm run migration:run   # crea la estructura de tablas
> npm run seed            # crea el usuario admin y datos de ejemplo
> ```
>
> ### 5. Levantar el proyecto en modo desarrollo
>
> ```bash
> npm run dev
> ```
>
> La aplicación estará disponible en <http://localhost:3000>.
>
> ### 6. (Opcional) Ejecutar con Docker
>
> ```bash
> docker compose up --build
> ```
>
> El contenedor escuchará en el puerto `3000` y usará la misma configuración del archivo `.env`.
>

## ⚙️ Configuración inicial

1. **Supabase** – crea un proyecto, habilita la base de datos PostgreSQL y copia la URL de conexión (`postgresql://...`).
2. **JWT secrets** – genera dos strings seguros (p.ej. con `openssl rand -hex 32`).
3. **Variables de entorno** – revisa `.env.example` para ver la lista completa y asegúrate de que no haya espacios ni comillas alrededor de los valores.
4. **Persistencia de tokens** – el refresh‑token se almacena **hasheado** en la tabla `refresh_token`; el `Idempotency‑Key` de las pujas se guarda en `idempotency_key`.

## 📜 Convenciones de código

- **TypeScript strict** – `noImplicitAny`, `strictNullChecks`, `exactOptionalPropertyTypes`.
- **Nombres descriptivos** – funciones y variables usan camelCase; tipos e interfaces PascalCase.
- **Capas** – *route handler* → *service* → *repository* (TypeORM). La lógica de negocio nunca está en los handlers.
- **Errores consistentes** – objeto `{ error: { code: string, message: string, details?: any } }` y códigos HTTP según la tabla de la skill.
- **Tests** – Jest con cobertura mínima del 80 %; pruebas unitarias enfocadas en reglas de negocio de pujas y estado de subasta.
- **Lint/Prettier** – configurado con `eslint` y `prettier`; `npm run lint` debe pasar sin errores.
